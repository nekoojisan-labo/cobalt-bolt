## 1. 目的・成功状態

- 立ち・走り・ジャンプのどの状態でも、バスターを肩から構えて攻撃している人体動作に見える。
- 走りながらチャージしても、脚は走り続け、上半身はバスターを狙って構え続ける。
- 通常立ち姿の腕も、肩から肘・手へ自然につながる。
- 通常立ち姿は常時しゃがまず、足裏を接地したまま骨盤・胸・頭が自然に積み上がる。
- 頭・胸郭・骨盤・四肢が同じ視点、同じ比率、同じ一体マスターに由来し、一人の完成体として見える。
- 主人公とボスはそれぞれ一つの3Dモデルと一つの骨格を全動作で共有し、装甲形状・体積・関節位置が変化しない。
- ゲーム内では従来どおり透過2Dスプライトとして表示し、実行時に3Dエンジンを追加しない。

## 2. 状態別の承認内容

| 状態 | 下半身 | 上半身・腕 |
|---|---|---|
| 立ち撃ち | 両足を接地して踏ん張る | 胸を安定させ、肩→肘→バスターを前へ向け、発射時だけ小さく反動 |
| 走り撃ち | 走行サイクルを維持 | 上体の揺れを抑え、肩から照準姿勢を維持 |
| ジャンプ撃ち | 上昇・頂点・下降の脚姿勢を維持 | 上体を少し起こし、空中でも肩から前方へ照準 |
| 走りチャージ | 走行サイクルを維持 | 発射反動なしで照準姿勢を保持し、砲口の蓄光だけ成長 |
| 通常立ち | 両足を自然に接地し、膝は軽く緩める | 体幹をほぼ垂直にし、肩から腕が下がり、肘が人体として自然に曲がる |

## 3. 禁止状態

- 腕が顔・首・胸の中央から生えて見える。
- 肩と上腕、上腕と前腕の間が離れる、または不自然に重なる。
- 通常立ち腕が棒状に垂れる、足元まで届く、胴体へ埋まる。
- 通常立ちで両膝が深く曲がり、常に腰を落とした前傾・しゃがみ姿勢に見える。
- 立ち姿の補正によって足裏が地面から浮く、または接地点が横へずれる。
- 別々に生成した体幹・腕・脚を、見た目が似ているだけで接続する。
- 手前側と奥側へ同じ四肢画像を複製し、遠近・光・装甲形状が一致して見える。
- 頭・胸・骨盤を一枚の硬いパーツにまとめ、首・背骨・骨盤の連動を失う。
- すねと足を一体化し、接地中の足裏を地面へ残せなくする。
- 一方向の立ち絵だけから3D形状を推測し、正面・側面・背面で装甲や比率が変わる。
- 動作ごとに別の3Dモデルを作り、体型や武器サイズが変わる。
- アニメごとにカメラ角度、焦点距離、照明、接地基準を変える。
- ブラウザ実行時にリアルタイム3Dを導入し、現在の2Dゲームの負荷や互換性を変える。
- 有料の画像3D生成サービス、有料モデル、有料アドオンを前提にする。
- 参照画像をモデルへ投影し、合っていない立体形状を絵柄で覆って完成判定する。
- 正面だけを細切れの板状パーツで合わせ、側面・背面・斜めから一体の装甲として成立しない。
- 走りチャージ中に腕が走行スイングへ戻る。
- 走り撃ち・ジャンプ撃ちで下半身が立ち姿へ切り替わる。
- 状態ごとに砲口と弾の発生位置がずれる。
- 走行中、腿が水平のまま長く残って高足の行進・前蹴りに見える。
- 接地脚の膝が伸び切り、骨盤がその上を通過せず棒立ちのまま脚だけが交換される。
- 前へ進む映像で、着地足より先に骨盤が進む、接地足がキャラクターと一緒に滑る、または遊脚が骨盤より後ろに残ったまま次の接地へ切り替わる。
- 片脚を前後へ振るだけで、支持脚の蹴り出しと両足が離れる空中局面がシルエットから判別できない。
- 走りの接地コマと空中コマの間で、骨盤・足・腕が瞬間移動して見える。
- 射撃・チャージ中の反対腕が後方へ水平に伸び、Tポーズやカウンターウェイトに見える。
- スプライト内のジャンプ軌道とゲーム側の `player.y` を同時に加算し、二重に上下させる。
- 全身表示では動いていても、実ゲームサイズで呼吸・反動・発光・関節の変化が読めない。
- 8コマ出力へ固執し、1コマ8ワールドpxの移動に脚が届かない状態で足を接地させる。
- 射撃フラッシュやチャージ球を走行・ジャンプの特定コマへ焼き込み、入力時刻と無関係に自動点滅させる。
- 腿角だけを一律に拡大し、前脚を水平に伸ばす前蹴り・行進のシルエットを強める。
- 空中局面を長く取りすぎ、接地と蹴り出しより脚を前後交換する時間の方が長く見える。
- 通常走りで体幹・肩・肘がほぼ固定され、脚だけを交換しているように見える。
- 夜背景と同程度の濃紺・黒が装甲と関節の大半を占め、実ゲームサイズで四肢の境界が消える。

## 4. 不変条件

- 骨盤→体幹→肩→肘→バスターの親子関係を全状態で共有する。
- 上腕・前腕・脚の骨長を状態間で変えない。
- 弾とマズルFXは描画と同じ砲口座標から発生する。
- 移動速度、ジャンプ物理、当たり判定、敵、ステージ進行を変更しない。
- ゲーム内テスト反映はローカル作業に限定し、ユーザーの追加指示なしにGitHub Pagesへ公開しない。
- 走行1周期はゲーム側の64ワールドpx移動と一致させ、時間だけでなく移動距離からフレームを選ぶ。
- 走行20コマは1コマ3.2ワールドpx、60fpsとし、ゲーム更新1tickと一対一で対応させる。
- 通常走り・走り撃ち・走りチャージは、同一フレーム番号で骨盤・脚・足首・接地位置を完全共有する。
- 通常ジャンプ・ジャンプ撃ちは、同一の踏切・上昇・頂点・下降・着地の下半身姿勢を共有する。
- マズルフラッシュ、チャージ球、弾はスプライトへ焼き込まず、全コマから書き出す同一の砲口アンカーへゲーム側で重ねる。
- 大振り化と明度調整で、承認済みの体型、骨長、装甲形状、カメラ、足元アンカー、砲口ソケットを変更しない。
- 明度調整はゲーム書き出し用の材質・照明設定に限定し、承認済み形状マスターを作り直さない。

## 5. 検証方法・受け入れ基準

- 通常立ち、立ち撃ち、走り撃ち、ジャンプ撃ち、走りチャージを同じ倍率で画像化する。
- 各画像で肩の接続、肘の曲がり、胴との重なり、砲口位置を目視確認する。
- 状態別の腕・体幹値が同一値の使い回しでないことを自動検査する。
- 走りチャージ中も `charge` の構えを維持することを自動検査する。
- 既存の全身関節検査とゲーム進行30項目を通す。
- 実ブラウザで操作し、表示エラー0を確認する。
- 走行20コマを実ゲームの64px/周期へ換算し、接地足の世界座標ずれを各接地区間で0.5ワールドpx以内にする。
- 走行は接地・荷重・通過・空中の4局面を左右対称に持ち、接地脚の膝を完全伸展させない。
- 接地開始では着地足の足裏中心を骨盤より前へ置き、支持後半では骨盤が同じ接地点を越えて前へ出る。この前後関係が接地区間内で逆転することを世界座標で検査する。
- 空中局面では次の着地脚の膝が骨盤より前へ抜け、着地準備で同じ脚の足裏中心も骨盤より前へ到達することを世界座標で検査する。
- 接地中の足裏と地面に印を付け、キャラクターを実ゲーム速度で前進させる診断動画を必須とする。固定位置で足踏みする動画を「実ゲーム確認」と呼ばない。
- 走行・ジャンプの隣接コマは腿角差20度以内、膝角差25度以内とし、踏切・離地・着地で一コマだけ関節が跳ばないことを確認する。
- 走り・走り撃ち・走りチャージを実ゲーム相当の60fps、約35ワールドpx高で並べ、足滑り・行進・空中コマの跳ねがないことを動画で確認する。
- 走行の両腿は一周期で前後合計70度以上の可動域を持ち、通常走りの反対側の手は画面上で24ソースpx以上移動する。数値だけで合格にせず、前蹴りではなく肩からの腕振りと膝先行の回収に見えることを動画でも確認する。
- 両足が地面から離れる空中局面は左右それぞれの半周期に2コマ以上連続して持つ。20tick/64pxと脚の非伸縮リーチを優先し、コマ数だけでなく離地直後の後脚伸展、先行する膝、着地準備の順序で走行と判定する。
- 通常走り・走り撃ち・走りチャージの同一フレームで、骨盤・腿・膝・足首・足裏の変換行列が完全一致することを自動検査する。
- 透過スプライトの不透明画素は、全8状態で輝度中央値55以上、輝度55未満の割合50%以下を目標とし、通常走りでは輝度中央値60以上を必須とする。夜背景に合成した実ゲーム画面でも青装甲と関節の輪郭を目視確認する。
- 射撃・チャージ中の反対肘は胴体近くで曲げ、手先が肩と同じ高さのまま後方へ水平に伸びないことを全フレームで確認する。
- ジャンプの制作スプライトではルート上下移動を0とし、ゲーム物理を加えたプレビューだけで踏切から着地までの弧を確認する。
- ジャンプ全コマの `CTRL_root.z` を実測し、許容誤差 `1e-6` 以内で0であることを確認する。レビュー上の上下動はレンダー時だけ別レイヤーで加える。
- 実ゲームサイズで、通常弾の発光は直径3画面px以上、チャージ発光は直径6画面px以上、反動は砲口または肩で2画面px以上読めることを確認する。
- すべてのモーションで頭頂フィン、砲口、つま先がフレーム端から2画面px以上内側に収まり、クリップしないことを確認する。
- 通常立ちの膝の曲がりを左右とも15〜35度、体幹傾斜を絶対値1度以内に保つ。
- 通常立ちの補正後も、走り・ジャンプ・攻撃・チャージの状態別ポーズが変わっていないことを確認する。
- 量産・パーツ分割・ゲーム実装の前に、一体型の直立マスターを実ブラウザで表示して視覚承認を得る。
- マスターの頭身は承認済み三面図の主要点を正本とし、頭頂フィンから顎までを1頭身と数えて概ね5頭身とする。文字上の頭身指定より三面図の顎・肩・胸・股・膝・足首位置を優先する。
- 首、肩、肘、骨盤、股関節、膝、足首が目視可能で、手前側と奥側の四肢を区別できること。
- 承認後の骨格階層は、骨盤→腹部→胸→首→頭、胸→肩→肘→手、骨盤→股関節→膝→足首→足を共有する。
- 3D制作前に主人公の正面・右側面・背面図を作り、同一の頭身・装甲・バスター・関節位置として実ブラウザで承認を得る。
- Blenderファイル内に承認済み三面図をレンダー対象外の参照面として配置し、正面・右側面・背面の各ビューでモデルと直接比較できるようにする。
- 初回の箱・球・円柱を並べたブロックアウトは完成形として使わず、胸郭・骨盤・太腿・脛・前腕バスターを先細りする輪郭メッシュで造形する。
- 正面と右側面で、頭頂、顎、肩、胸最幅、腰最細、股、膝、足首、足裏の主要9点を三面図へ合わせる。各点の高さ差は全高の3%以内、横幅差は該当部位幅の10%以内を目標とする。
- 細部装甲や動作を作る前に、無地のシルエットレンダーで「細い腰、長い脚、関節のくびれ、先細りのバスター」が三面図と一致することを確認する。
- 最初の造形ゲートでは参照画像の投影・焼き付けUV・装飾テクスチャを使わず、全身を同じ中間色、関節だけを暗色にした粘土レンダーで比較する。
- 正面・右側面・背面を三面図の各キャラクターへ同じ全高と足裏位置で重ね、50%透過画像を保存する。頭頂・顎・肩端・胸郭端・腰端・股・膝中心・足首・爪先・踵・砲口のずれを可視化する。
- 粘土レンダーの合格条件は、主要点の高さ差が全高の2%以内、左右輪郭差が該当部位幅の8%以内で、頭部、胸郭、骨盤、左右前腕、左右腿、左右脛、左右足の各輪郭が連続した立体として読めることとする。
- 正面・右側面・背面の粘土重ね合わせに一つでも明白な破綻があれば、UV・材質・リグ・動作制作へ進まない。
- 斜め45度の粘土レンダーで、正面板と側面板の交差、浮いた装甲、体幹の空洞、関節から外れた四肢がないことを確認する。
- 造形は左右対称の基礎体積を単一または少数の連続メッシュで作り、頭部・胸郭・骨盤・上腕・腿・脛・足の体積確定後に固有装甲を分離する。
- 主要9点とシルエット比率は初期形状の検査にだけ使い、完成承認の代用にしない。
- 完成候補は、頭部フィンとバイザー、胸部コアと左右胸装甲、腹部の段差、骨盤装甲、肩・肘・膝・足首の関節露出、左右非対称の前腕、バスター砲口、脛装甲とブーツの各項目を三面図と並べて確認する。
- 青・濃紺・銀・黒・シアン発光部の配置、装甲面のハイライト、関節部の非金属感が三面図と同じ役割に見えることを確認する。
- 正面・右側面・背面のいずれかで固有装甲の形状または配置が欠けるモデルは、人体比率が合っていても完成候補にしない。
- 主人公は `idle/run/jump/shoot/charge/hurt/runshoot/jumpshoot` を同じ3Dモデルからレンダリングする。
- ボスは `idle/jump/shoot/dash/death` を同じ3Dモデルからレンダリングする。
- Blenderは固定の正投影カメラ、固定照明、透明背景、足元中央アンカーを共有する。
- 書き出し後は主人公256×256、ボス512×512の既存フレーム規格へ収め、当たり判定・物理・ゲーム進行を変更しない。

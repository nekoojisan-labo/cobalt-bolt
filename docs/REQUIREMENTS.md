## 1. 目的・成功状態

- 立ち・走り・ジャンプのどの状態でも、バスターを肩から構えて攻撃している人体動作に見える。
- 走りながらチャージしても、脚は走り続け、上半身はバスターを狙って構え続ける。
- 通常立ち姿の腕も、肩から肘・手へ自然につながる。
- 通常立ち姿は常時しゃがまず、足裏を接地したまま骨盤・胸・頭が自然に積み上がる。
- 頭・胸郭・骨盤・四肢が同じ視点、同じ比率、同じ一体マスターに由来し、一人の完成体として見える。
- 主人公とボスはそれぞれ一つの3Dモデルと一つの骨格を全動作で共有し、装甲形状・体積・関節位置が変化しない。
- ゲーム内では従来どおり透過2Dスプライトとして表示し、実行時に3Dエンジンを追加しない。

## 2. 状態別の承認内容

| 状態 | 下半身 | 上半身・腕 |
|---|---|---|
| 立ち撃ち | 両足を接地して踏ん張る | 胸を安定させ、肩→肘→バスターを前へ向け、発射時だけ小さく反動 |
| 走り撃ち | 走行サイクルを維持 | 上体の揺れを抑え、肩から照準姿勢を維持 |
| ジャンプ撃ち | 上昇・頂点・下降の脚姿勢を維持 | 上体を少し起こし、空中でも肩から前方へ照準 |
| 走りチャージ | 走行サイクルを維持 | 発射反動なしで照準姿勢を保持し、砲口の蓄光だけ成長 |
| 通常立ち | 両足を自然に接地し、膝は軽く緩める | 体幹をほぼ垂直にし、肩から腕が下がり、肘が人体として自然に曲がる |

## 3. 禁止状態

- 腕が顔・首・胸の中央から生えて見える。
- 肩と上腕、上腕と前腕の間が離れる、または不自然に重なる。
- 通常立ち腕が棒状に垂れる、足元まで届く、胴体へ埋まる。
- 通常立ちで両膝が深く曲がり、常に腰を落とした前傾・しゃがみ姿勢に見える。
- 立ち姿の補正によって足裏が地面から浮く、または接地点が横へずれる。
- 別々に生成した体幹・腕・脚を、見た目が似ているだけで接続する。
- 手前側と奥側へ同じ四肢画像を複製し、遠近・光・装甲形状が一致して見える。
- 頭・胸・骨盤を一枚の硬いパーツにまとめ、首・背骨・骨盤の連動を失う。
- すねと足を一体化し、接地中の足裏を地面へ残せなくする。
- 一方向の立ち絵だけから3D形状を推測し、正面・側面・背面で装甲や比率が変わる。
- 動作ごとに別の3Dモデルを作り、体型や武器サイズが変わる。
- アニメごとにカメラ角度、焦点距離、照明、接地基準を変える。
- ブラウザ実行時にリアルタイム3Dを導入し、現在の2Dゲームの負荷や互換性を変える。
- 走りチャージ中に腕が走行スイングへ戻る。
- 走り撃ち・ジャンプ撃ちで下半身が立ち姿へ切り替わる。
- 状態ごとに砲口と弾の発生位置がずれる。

## 4. 不変条件

- 骨盤→体幹→肩→肘→バスターの親子関係を全状態で共有する。
- 上腕・前腕・脚の骨長を状態間で変えない。
- 弾とマズルFXは描画と同じ砲口座標から発生する。
- 移動速度、ジャンプ物理、当たり判定、敵、ステージ進行を変更しない。

## 5. 検証方法・受け入れ基準

- 通常立ち、立ち撃ち、走り撃ち、ジャンプ撃ち、走りチャージを同じ倍率で画像化する。
- 各画像で肩の接続、肘の曲がり、胴との重なり、砲口位置を目視確認する。
- 状態別の腕・体幹値が同一値の使い回しでないことを自動検査する。
- 走りチャージ中も `charge` の構えを維持することを自動検査する。
- 既存の全身関節検査とゲーム進行30項目を通す。
- 実ブラウザで操作し、表示エラー0を確認する。
- 通常立ちの膝の曲がりを左右とも15〜35度、体幹傾斜を絶対値1度以内に保つ。
- 通常立ちの補正後も、走り・ジャンプ・攻撃・チャージの状態別ポーズが変わっていないことを確認する。
- 量産・パーツ分割・ゲーム実装の前に、一体型の直立マスターを実ブラウザで表示して視覚承認を得る。
- マスターは約4.5頭身、右向き斜め側面、足裏同一線、直立、右前腕バスター、左手通常腕とする。
- 首、肩、肘、骨盤、股関節、膝、足首が目視可能で、手前側と奥側の四肢を区別できること。
- 承認後の骨格階層は、骨盤→腹部→胸→首→頭、胸→肩→肘→手、骨盤→股関節→膝→足首→足を共有する。
- 3D制作前に主人公の正面・右側面・背面図を作り、同一の頭身・装甲・バスター・関節位置として実ブラウザで承認を得る。
- 主人公は `idle/run/jump/shoot/charge/hurt/runshoot/jumpshoot` を同じ3Dモデルからレンダリングする。
- ボスは `idle/jump/shoot/dash/death` を同じ3Dモデルからレンダリングする。
- Blenderは固定の正投影カメラ、固定照明、透明背景、足元中央アンカーを共有する。
- 書き出し後は主人公256×256、ボス512×512の既存フレーム規格へ収め、当たり判定・物理・ゲーム進行を変更しない。

## 6. スコープ外

- 既存の個別生成2Dパーツを継ぎ足し、主人公・ボスの正本として使い続けること。
- 移動速度、攻撃力、チャージ時間などゲームバランスの変更。
- 雑魚敵の3D化とモーション変更。
- ゲーム本体のリアルタイム3D化。
